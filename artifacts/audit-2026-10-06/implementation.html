Acceptance scenarios

  1. M01 — retained edits: Use a synthetic project with scene, manuscript and Research content. Type distinct markers in each editor and immediately lock/background the device, then terminate and reopen. Repeat offline, with cloud-only files, with two dirty panes and with an unresolved disk conflict. Every marker must be saved or offered for recovery; a newer disk version must not be silently replaced. Test the normal acknowledged flush and a deliberately interrupted flush separately. Record whether the OS granted background execution rather than treating every forced termination as the same lifecycle event.
  2. M02 — security scopes: In a disposable debug checkout, count successful StartAccessingSecurityScopedResource returns and matching native stop calls in the SecurityScopedFolders partial files. Count release-callback execution, not its registration. Failed starts do not acquire a lease. Use counter-only breakpoints or temporary counters, without logging project paths. Repeatedly open, cancel, close and reselect external folders and manuscript imports; after each settled operation, acquisitions minus releases must equal the retained active-project/import baseline. Closing the import dialog releases its temporary grant; disposing the page releases its grants. Reload after a WebKit failure with an import selection retained, then deliver a delayed picker result to the old page: it must be rejected/released without disturbing the new page's grants. Include a bookmarked parent with two projects: move the parent in Files and reopen both children from recents. Restore the debug-only instrumentation before the final clean build.
  3. M03 — container relocation: Keep app-owned synthetic projects and an external project whose suffix matches one of them. Exercise an actual update/restore that changes the app data-container location while preserving its data. Confirm app-owned recents resolve by recorded provenance and stable project ID; the external matching suffix must not redirect. Record whether the container actually changed, without publishing its path. If it did not change, this case remains untested even if reopening works.
  4. M04 — transport failure: Open a fixture, retain an unsaved marker, then inject each fault separately using the procedure below. Pending calls must reject, editing must pause, and the native Reload/Later alert must remain available. Reload once; retained edits must recover without replaying a mutation. A simulated callback is not evidence that a real WebKit termination was observed.
  5. M05 — Apple gate and device smoke: Confirm the actual Apple PR job runs for Core-only, SDK-only and renderer-only changes. In a disposable checkout, add an invalid symbol to an iOS-compiled source file and confirm the same simulator build fails. Remove the probe and obtain a clean passing build. On the signed device, create/open, edit and relaunch a project; import a fixture and share an export. Do not mark the CI path-trigger case passed from a local build alone.
  6. M06 — microphone: Deny microphone permission and check the permission-specific explanation. Enable access in iOS Settings and retry: recording should start, stop once, and clear the stale error. Interrupt recording with backgrounding or another audio session. The portable denial/retry regression passes through the real shim and dictation store, but does not exercise the system prompt or AVAudioSession.
  7. R13/R14 — native media: Exercise scene/map images, PDF/audio/video Research attachments, rapid source/project switches, and files above the 16 MiB preview limit. In a disposable debug build, add a one-shot asynchronous TaskCompletionSource gate after the native read captures its bytes/root and before replying. Keep the UI running, switch the selected source/project, then release the reply; a breakpoint freezing the process cannot test this race. The old reply must not replace the current preview. Verify every stored reference is still project-relative, and oversized content remains intact on disk with a visible preview error. Confirm callbacks complete after dismissal without restoring an obsolete preview.
  8. R15 — focus: On iPhone, navigate inspector sheets with VoiceOver swipe and rotor navigation. On iPad, use a hardware keyboard for Tab, Shift+Tab and Escape, including a nested dialog. Focus must enter the sheet, stay out of the covered editor, and return to the inspector button. Repeat portrait and landscape. Desktop browser focus tests do not establish native accessibility behavior.
  9. Alternate at least five fresh-process launches, record launch-to-usable time and peak app/WebKit memory, and capture a separate JavaScript parsing trace. Record the device model, OS, thermal state and whether caches were controlled. Open every Help page and decode all 11 screenshots in airplane mode. M04 fault injection in a disposable debug build

Attach a debugger to the test app and use Novalist.Mobile/Pages/RendererHostPage.Transport.cs and RendererHostPage.cs. Arm one fault only after the fixture is open and the unsaved marker is retained. Trigger a harmless read such as opening Settings; do not deliberately replay a save. Remove each probe and rebuild before the next case.

  • Evaluator failure: Temporarily make the next call inside DeliverCallbackAsync return a faulted Task<string> with an IOException, then restore ordinary evaluation. This exercises the native failure route without needing Safari inspection to be enabled.
  • Evaluator timeout: For one call only, substitute an uncompleted TaskCompletionSource<string>().Task for the evaluator task and keep the existing WaitAsync timeout intact. Expect the 15-second delivery deadline, followed by at most the 2-second notification attempt before the native alert. Keep the UI thread running; a breakpoint that freezes the entire process cannot test the timeout.
  • Backend pump failure: Dispose only this test page's _bridge after readiness, then resume execution. Confirm the read failure reaches FailBridgeAsync and pending JavaScript operations reject. This is a transport fault probe, not a normal disposal test.
  • Real WebKit termination: Identify the WebContent process belonging to this isolated simulator/test app before terminating it with the debugger or Activity Monitor. Confirm WebProcessObserver.ContentProcessDidTerminate is invoked. Do not terminate all WebKit processes. If association cannot be established, leave this case pending; directly invoking the observer only checks the handler.
