# Import through a local REST API

An external agent can read your source folder, request Novalist's current types and schemas, and send structured entries directly into your open project.

1. Open the destination project, book, and draft in the desktop app.
2. Open **File → Import a folder…** and turn on **Local import API**.
3. Press **Copy agent instructions** and give those instructions and your source folder to your chosen agent. If you already selected a folder, its path is included in the instructions.

You can close the dialog and keep working. Reopen it to see import counts or turn **Local import API** off. The API stops when you change project, book, or draft, or close Novalist. Each start after stopping creates a new access token and an available local port.

The API listens on `127.0.0.1` and requires `Authorization: Bearer <token>` on every request, including schema discovery. Use the exact URL copied from Novalist; no port configuration or administrator access is needed. Give the token to the local agent you choose. The agent reads the source files and sends their converted data to Novalist. Novalist saves that data locally using the regular importer.

## Discovery and schemas

The base URL looks like `http://127.0.0.1:54321/v1`. Replace the example port with the actual one.

| Method | Path | Result |
| --- | --- | --- |
| GET | `/v1` | Instructions, destination, endpoints, request shape, and limits |
| GET | `/v1/types` | Built-in and custom type keys, display names, and schema paths |
| GET | `/v1/schema` | JSON Schema 2020-12 covering all currently available targets |
| GET | `/v1/types/{key}/schema` | A standalone schema and example for one target |
| GET | `/v1/status` | Session import, skip, and failure counts |
| POST | `/v1/import/validate` | Validate entries without saving them |
| POST | `/v1/import` | Validate and import entries, returning a result for each |
| POST | `/v1/images` | Upload one image as raw bytes; return its reusable `imageId` |
| POST | `/v1/images/attach` | Add uploaded pictures to an existing Codex entry, preserving its fields |

Schemas reflect the current book's active templates, custom Codex types, and manuscript properties. Fetch them again after changing those definitions. Their examples illustrate the format; the agent should fill values from your source material. See the [schema guide](README.md) for property types and supported fields.

## Send a batch

Send `Content-Type: application/json`. Each request contains **1–40 entries** and at most **8 MiB** of UTF-8 JSON. Stream a large dataset in successive batches, using smaller batches for large documents. A request can contain different target types.

```json
{
  "entries": [
    {
      "sourceId": "/my-source/characters/ada.md",
      "document": {
        "novalistImport": 1,
        "target": "character",
        "data": {
          "name": "Ada",
          "surname": "Lovelace",
          "eyeColor": "brown",
          "customProperties": { "Occupation": "Mathematician" }
        },
        "content": "Her preserved biography in **Markdown**."
      }
    },
    {
      "sourceId": "/my-source/manuscript/arrival.md",
      "folder": "Chapter 1",
      "document": {
        "novalistImport": 1,
        "target": "scene",
        "data": { "title": "Arrival", "synopsis": "Ada reaches the harbour." },
        "content": "Ada **entered** the harbour."
      }
    }
  ]
}
```

`sourceId` is a stable string of 1–2048 characters. Use the full source path, and append an entry suffix such as `#Ada` when splitting one file into multiple records. Keep it identical on retries and later imports. Novalist derives the stored ID from `sourceId` and `target`. Repeating the same pair skips the existing entry, preserving user edits, including across API restarts. Changing either creates another entry. Keep each source ID unique within its dataset.

Optional `folder` is a label of at most 256 characters. Scene entries with the same label share an imported chapter; omitted labels use **External import**. Slash-separated labels also contribute tags, as they do in folder imports. Storage paths are generated by Novalist.

Each `document` uses the same schema as a [JSON file import](README.md). Built-in properties retain their documented types; custom property values are strings, including `"true"`, `"42"`, and ISO dates. Required custom type fields must be supplied. Scene and research documents require Markdown `content`.

## Include images

Characters, locations, items, lore, and custom Codex types accept `data.images`. Upload each source image before validating or importing its document. Send **raw file bytes**, one image per request, with the matching `Content-Type`: `image/png`, `image/jpeg`, `image/gif`, `image/webp`, `image/bmp`, or `image/svg+xml`. Each image may contain at most **32 MiB**. The JSON request limit remains 8 MiB. Do not send base64 or a filesystem path in the image upload.

```sh
curl --request POST "$BASE_URL/images" \
  --header "Authorization: Bearer $TOKEN" \
  --header "Content-Type: image/png" \
  --data-binary @portrait.png
```

The response has `imageId` (64 lowercase hexadecimal characters), `contentType`, `bytes`, and `reused`. HTTP 201 means the image was stored; HTTP 200 with `reused: true` means the same bytes were already stored. Repeat uploads reuse the file, including after restarting the API. Novalist keeps its own copy inside the book, so moving the source folder does not break the picture.

Use the returned ID in the document, with the source image's label or filename and optional source alternative text:

```json
"images": [
  { "imageId": "<returned imageId>", "name": "Portrait", "alt": "Description from the source" }
]
```

`images` belongs inside `data`, with at most **100 references per entry**. Omit `alt` if unknown. Validation checks that all referenced images are available in the current book. Uploads remain available after stopping the API; references from another book must be uploaded again. Images are attached to the Codex gallery; scene and research schemas do not accept this field.

For an entry already imported without its pictures, repeating `/v1/import` still skips the existing entry and preserves edits. Use its `target` and returned `id` (from the `imported` or `skipped` result) to add the photos:

```json
{
  "target": "character",
  "id": "<imported or skipped result id>",
  "images": [ { "imageId": "<returned imageId>", "name": "Portrait" } ]
}
```

Send that object to `POST /v1/images/attach` as `application/json`. The response contains `target`, `id`, `added`, and `total`. It adds missing images while keeping authored text, fields, pictures, and captions. Repeating the same attachment adds nothing. Locked entries return HTTP 409 and must be unlocked in Novalist before adding pictures.

## Results and retries

Successful batch processing returns HTTP 200 with `results`, `imported`, `skipped`, `failed`, `validated`, and `validateOnly`. Inspect **every result**: a batch may contain both successful and invalid entries.

Each result has `sourceId`, `target`, `id`, `status`, and `error`. Status is `valid` for a successful validation, `imported`, `skipped` for an existing source, `invalid` for a schema or source-ID problem, or `failed` for an entry that could not be saved. Validation creates no files. Valid entries continue when another entry is invalid. Correct invalid documents using the current schema and resend them.

Malformed requests or mismatched image bytes return HTTP 400, an incorrect or missing token returns 401, a non-local host or browser-origin request returns 403, unknown endpoints, types, entries, or uploaded images return 404, and wrong methods return 405. Bodies over the limit return 413; incorrect content types return 415. A changed import session or locked attachment target returns 409; a queued request cancelled by stopping the API returns 410. HTTP 503 means a save failed: check disk space and permissions, then retry the batch with the same source IDs or upload the same image bytes again. Some entries may have already been saved, so stable source IDs are essential.

New entries appear in the Codex, Research, and manuscript as batches finish. Novalist runs API imports through the same workspace queue as the editor, saving manifests once per batch.
